# SULTRAKLIK — Laravel 12 + Filament 3 news portal

Indonesian-language news portal. All admin labels, seed content, comments, and frontend copy are in Indonesian — keep it that way in new code/UI strings.

- `project.md` (repo root) is the product spec. Read it for intent, but it is **wrong about roles**: it lists separate `roles`/`permissions` tables (`project.md:602-604`) and Spatie Permission (`:656`). The code uses a single `role` ENUM on `users`.
- `README.md` is unmodified Laravel boilerplate. It contains nothing about this project.

## Commands
- Setup (first time only): `composer run setup` — install → copy `.env.example` **only if `.env` is missing** → `key:generate` → `migrate --force` → `npm install` → `npm run build`. `.env` already exists here pointing at MySQL, so setup will not overwrite it.
- Dev: `composer run dev` runs `php artisan serve`, `queue:listen`, `pail`, and vite together. `npm run dev` = frontend only (and irrelevant to public pages, see below).
- Seed: `php artisan db:seed` sengaja **minimal** — hanya `UserSeeder` (satu akun super admin), `AdvertisementSeeder` (3 slot iklan demo), dan baris settings dasar. Isi artikel/kategori/wilayah/halaman/breaking news demo sudah dihapus: situs yang baru di-deploy harus kosong, dan menjalankan seeder artikel di produksi berarti menimpa konten redaksi. **Jangan menambahkan kembali seeder konten demo** tanpa alasan yang jelas. Test tidak memakai `DatabaseSeeder` sama sekali — mereka memakai `Tests\Fixtures\DemoContentSeeder`, yang hidup di `tests/` supaya tidak pernah ikut `db:seed`. Seeder/settings pakai `updateOrCreate` (aman diulang), tapi nilainya menimpa apa pun yang sudah diedit admin di panel. `AdvertisementSeeder` menghapus iklan yang `position`-nya bukan `homepage_top`/`sidebar`, jadi beware kalau menambah slot baru. Gambar placeholder iklan ditulis sebagai PNG asli oleh trait `GeneratesPlaceholderImages`, jadi butuh ekstensi GD (tanpa font TTF).
- `UserSeeder` sengaja tidak punya password default. Password dibaca dari `SUPER_ADMIN_PASSWORD`; di `APP_ENV=production` seeder **menolak jalan** kalau kosong atau < 12 karakter, dan kalau akunnya sudah ada passwordnya tidak disentuh sehingga `db:seed` ulang tidak menimpa password yang sudah diganti. Di lokal saja password acak dicetak sekali ke console.
- Test: `composer run test` (= `artisan config:clear` + `artisan test`). One class: `php artisan test --filter=PublicPagesTest`. One method: `php artisan test --filter=test_visitor_can_like_article`. 86 tests / 335 assertions, all green.
- Header dan breaking news dibungkus satu `<div class="sticky top-0 z-40">` di layout agar keduanya nempel sebagai satu blok; `<header>` sendiri sengaja **tidak** sticky. Jangan tambah offset `top-*` untuk breaking news — itu akan membuat bar lepas dari header. Sidebar home sticky di `lg:top-40` untuk menyisakan ruang bagi stack itu; kalau tinggi header berubah, angka itu ikut disesuaikan.
- Breaking news: ticker menampilkan semua baris yang cocok dengan `BreakingNews::scopeLive()` (`is_active` dan berada di dalam rentang `starts_at`/`ends_at`). Semua item live dirender **dua kali** dalam satu baris lalu digeser oleh loop CSS murni `translateX(-50%)` (`.breaking-marquee` + `@keyframes` di `<style>` layout), durasi `max(18, count * 9)`d, berhenti saat hover dan dimatikan di bawah `prefers-reduced-motion`. **Tanpa JS, tanpa panah.** **`ends_at` kosong = tidak pernah kedaluwarsa**; baris yang rentangnya sudah lewat diam-diam hilang dari beranda, dan itu penyebab paling umum "section breaking news tidak muncul".
- Format: `vendor/bin/pint` (Laravel preset, no `pint.json`). No ESLint/Prettier/PHPStan, no CI (`.github` does not exist), no `opencode.json`.

## Environment
- `.env` is **MySQL** (`sultraklik`, 127.0.0.1, root, empty password) with `session`/`queue`/`cache` drivers = `database` — all three tables come from the framework migrations. MySQL must be up for `migrate`/`db:seed`/serving/tinker, but **not** for tests. `.env.example` says SQLite and is misleading; `database/database.sqlite` is a leftover.
- **Always render a stored file with `Storage::disk('public')->url($path)`** — that is the single most common cause of "uploaded images don't appear". The trap is subtle: `Storage::url()` is built from the **configured** disk url (i.e. `APP_URL`), while `asset()` is built from the **current request root** (`UrlGenerator::url()` uses `$this->request->root()` when a request exists). So it is `Storage::url()`, *not* `asset()`, that emits the wrong origin — with `APP_URL=http://localhost` and dev served on `:8000`, `Storage::url()` yields `http://localhost/storage/...`, a cross-origin URL. CSP `connect-src 'self'` then blocks Filament's `FileUpload` preview `fetch()`, and public `<img>` 404s because nothing listens on port 80. Fix by making the disk url itself root-relative: `config/filesystems.php` sets the public disk `'url' => '/storage'`, so every `Storage::disk('public')->url()` call returns a same-origin `/storage/...`. `asset('...')` remains fine for real files in `public/` (e.g. `asset('images/viteks-logo-light.png')`) because it tracks the request origin. `PublicPagesTest::test_storage_urls_stay_on_the_current_origin` and `SecurityTest::test_editor_upload_stores_file_on_public_disk` guard this.
- `public/storage` symlink exists. Files under `storage/app/public` are served **statically by `php artisan serve` before Laravel routing**, so the `storage.local` route (auto-registered for the `local` disk, root `storage/app/private`, because of its `'serve' => true`) never intercepts them. A path that exists only in `app/private` returns **403** — that is the signature of a file saved to the wrong disk, not a missing symlink.
- `.env` has `FILESYSTEM_DISK=local`, but that does **not** affect Filament: `FileUpload`/`ImageColumn` resolve their disk from `config('filament.default_filesystem_disk')`, which defaults to `'public'` in Filament's own bundled config (`vendor/filament/support/config/filament.php:44`) — no `config/filament.php` is published here. Prefer writing `->disk('public')` explicitly anyway so a later published config cannot silently redirect uploads to `storage/app/private`, which returns **403**.
- **`Filament\Tables\Columns\ImageColumn` cannot take a URL from an accessor.** `getImageUrl()` (`ImageColumn.php:149`) only returns the state verbatim when `filter_var($state, FILTER_VALIDATE_URL)` passes or it starts with `data:`. A root-relative `/storage/...` fails that check, so it falls through to `Storage::disk($this->getDisk())->url($state)` and `$storage->exists($state)` — producing `/storage/storage/...` or no image at all. Therefore **always pass the raw relative column plus `->disk('public')`**, never `->getStateUsing(fn ($r) => $r->some_url)`. `AdvertisementResource` hit this; `ArticleResource` and `MediaResource` are already correct. Plain `<img src="{{ $model->some_url }}">` in Blade is fine — that is raw HTML.
- `APP_DEBUG=true` in `.env` — this is why Livewire/Blade errors surface loudly in dev.

## Cloudflare & domain
- Domain produksi adalah **`sultraklik.id`** (bukan `.com`). `APP_URL=https://sultraklik.id` di `.env.example`, plus placeholder login `admin@sultraklik.id` dan `general.email` = `redaksi@sultraklik.id`.
- Login dilindungi **Cloudflare Access** (Zero Trust) sebagai gerbang OTP/Google di depan `/admin`. Halaman login Filament **tetap ada dan tidak berubah** — Access hanya membatasi siapa yang boleh mencapai halaman itu. Tidak ada integrasi OIDC ke Laravel.
- `App\Http\Middleware\TrustProxies` di-**prepend** di `bootstrap/app.php` (bukan append) — wajib jalan sebelum middleware lain membaca `request->ip()` atau `request->isSecure()`. `TrustedProxyTest` mengunci urutan itu.
- **Jangan pernah pakai `trustProxies(at: '*')` di sini.** Kalau seluruh internet dipercaya, `X-Forwarded-For` palsu bisa dipakai siapa pun untuk lolos dari rate limit komentar/like/login. Daftarnya harus hanya rentang resmi Cloudflare (`TRUSTED_PROXIES` di `.env`, default kosong = tidak ada proxy tepercaya, jadi dev lokal tanpa Cloudflare tetap benar).
- Rantai XFF dibaca Symfony **dari kanan ke kiri** (`normalizeAndFilterClientIps`, `vendor/symfony/http-foundation/Request.php:2214`): entri yang ada di daftar tepercaya dibuang, sisanya dibalik, dan `[0]` dipakai sebagai client IP. Cloudflare *menambahkan* IP asli di ujung kanan, jadi ujung kanan itulah yang menang dan angka palsu di ujung kiri terbuang. Kalau daftar IP Cloudflare berubah, sumbernya `https://www.cloudflare.com/ips-v4` dan `/ips-v6`.
- `AppServiceProvider::boot()` membaca `config('app.url')`, bukan `isSecure()`, untuk menyalakan `session.secure`/`http_only`/`same_site=lax`. `lax` **wajib**: `strict` akan membuang cookie sesi saat Cloudflare mengarahkan user balik ke aplikasi setelah OTP, sehingga orang terjebak loop login.
- Origin **hanya boleh** dijangkau lewat Cloudflare. Kalau IP server masih terbuka publik, seluruh daftar IP di atas jadi tidak berarti karena request bisa datang langsung. Pakai Cloudflare Firewall Rules atau batasi di `security group`.
- Yang harus dimatikan di dashboard Cloudflare: **Rocket Loader** (merusak Alpine.js dan `x-data` inline), dan **caching HTML untuk `/admin*`, `/up`, dan respons apa pun yang membawa `Set-Cookie`**.
- SSL/TLS mode **Full (strict)**, bukan Flexible. `public/storage` symlink **wajib dibuat ulang di server** (`php artisan storage:link`): symlink yang ada di repo ini absolut ke path Windows, jadi tidak akan benar di Linux.

## Captcha (Cloudflare Turnstile)
- Login admin dan form komentar dilindungi Turnstile. Semua lewat `App\Support\Turnstile::verify()`; Blade-nya satu komponen `resources/views/components/turnstile.blade.php` dengan atribut `action` (`login` / `comment`) dan `livewire` (nama property, opsional).
- **Aktif hanya kalau site key + secret key terisi** (`config/turnstile.php`). Default kosong → captcha mati, `php artisan test` dan dev lokal tidak perlu key. `TURNSTILE_ENABLED=false` mematikan secara eksplisit; itu juga jalur akses darurat kalau widget gagal dimuat.
- `Turnstile::verify()` **fail closed**: token kosong, `success: false`, HTTP 5xx, atau `ConnectionException` semuanya menolak. Jangan diubah jadi `fail open` — itulah yang membuat captcha tidak berguna.
- `action` wajib cocok dengan `data-action` di widget. Widget login mengirim `login`, widget komentar `comment`; token satu tidak bisa dipakai di form lain.
- **Login Filament passing token lewat argumen ketiga**, bukan dari body request: `Turnstile::verify(request(), Turnstile::ACTION_LOGIN, $this->turnstileToken)`. Form login milik Livewire, jadi token ada di state Livewire (`turnstileToken`), bukan field `cf-turnstile-response`. Ini sempat jadi bug yang akan mengunci admin total — jangan dikembalikan ke `request()->input()`.
- **Token Turnstile hanya sekali pakai.** Karena itu `Login::invalidateCaptcha()` dipanggil saat captcha gagal **dan** saat password salah (lewat `catch (ValidationException)`), lalu mendispatch event `sl-turnstile-failed` supaya widget di-reset. Tanpa reset itu, satu ketikan salah cukup membuat admin terkunci karena widget masih menampilkan "sukses" dan tidak menghasilkan token baru.
- Blade komponen pakai `wire:ignore` supaya morph Livewire tidak menyentuh DOM widget, dan callback global `window.slTurnstileCallback` meneruskan token ke Alpine lalu ke `$wire.set()`. Parameternya dikirim sebagai `@js()`, yang keluar sebagai kutip tunggal sehingga tidak merusak atribut HTML.
- `turnstile.hostnames` **default kosong = tidak diperiksa**. Hostname sudah terikat ke site key kita, jadi token situs lain tidak akan lolos; Hostname-check hanya bisa mengunci admin kalau `www` dan non-`www` beda.
- CSP wajib memuat `https://challenges.cloudflare.com` di `script-src`, `connect-src`, **dan** `frame-src` (widget iframe). `TurnstileTest` mengunci ketiganya.
- Ganti `config/security.php` kalau menambah CDN baru; jangan hanya menambahkannya di satu direktif.

## Routing (highest-risk area)
- `routes/web.php:35` ends with `Route::get('/{article:slug}')` — a catch-all for article slugs at the domain root. **Every** new route (admin, search, kategori, sultra, page, feeds) must be registered above it.
- `Article::RESERVED_SLUGS` (`app/Models/Article.php:31`) is the canonical list of first segments that must not be claimed by an article slug. `Article::normalizeSlug()` (`:221`) runs on every save and appends `-berita` to a reserved value, so a slug of `search` becomes `search-berita` rather than becoming unreachable. **Add to that constant when you add a top-level route.**
- Article pages 404 unless `Article::isPublished()` (status `published` **and** `published_at` in the past). `ArticleController` increments `views` at most once per IP+UA per 30 min (`Cache::add`).

## Frontend reality check
- The public site does **not** use the Vite bundle. `resources/views/components/layouts/app.blade.php` loads Tailwind from `cdn.tailwindcss.com`, Alpine 3 from jsDelivr, plus Font Awesome / Google Fonts CDNs, and injects a runtime `tailwind.config` that **replaces the `red` and `accent` color scales** with shades derived from `theme.primary_color` / `theme.accent_color`. So `bg-red-600` in Blade means "brand color" and changes with the setting. Editing `resources/css/app.css` or running `npm run build` does **not** affect public pages. `@vite` appears only in `resources/views/welcome.blade.php`, which no route serves.
- `App\Support\ColorPalette::shades()` is the single source of that 50–950 scale (invalid hex falls back to `#dc2626`). It is consumed by both the Blade layout and `AdminPanelProvider` — change it there, not in either consumer.
- The layout is a **Blade component** (`<x-layouts.app>`), so it has an isolated variable scope: controller data only reaches it if declared in its `@props` array and passed as an attribute. A `$var ?? default` fallback hides the bug — the variable is silently always undefined, so a `->count()`/`->isNotEmpty()` on it throws "Undefined variable" instead. Declare it in `@props` when you need it.
- All frontend JS is inline Alpine inside that layout: `liveSearch()` (→ `/search/live`), `homeLoadMore()` (→ `/home/load-more`), `themeToggle()`, `cardLike()`, `cardShare()`. `resources/js/app.js` only imports bootstrap; do not look for JS modules.
- The article page (`articles/show.blade.php:86-99`) uses hardcoded Facebook/WhatsApp/X share links, while cards use `cardShare()` via `components/card-actions*.blade.php`. Not the same — don't assume the dropdown exists on the article page.
- `/home/load-more` renders `components.news-card` server-side and returns `{html, ids, hasMore}`. `HomeController::index()` de-dupes across headline → videos → latest → popular → pilihan → recommended → wilayah via one shared `$usedIds` list, exported to the view as `pageUsedIds` and passed into `homeLoadMore()`. A new home section must extend that list or articles will repeat.
- Navbar active state is computed in the layout's top `@php` block (`$navIsHome`, `$navIsSultra`, `$navIsSearch`, `$navIsCategory()`, `$navIsPage()`, plus the `$navClasses` / `$navClassesDrawer` string builders). It used to be a hardcoded `text-red-600 border-b-2 border-red-600` on the BERANDA link, so "Beranda" looked active on every page. Categories are also highlighted while reading an article, via the layout's `article` prop — add a new nav entry there, don't hardcode a class.
- **Never write `@class="[...]"` in this layout.** Blade has its own `@class($array)` directive and it collides with Alpine's `@class` attribute syntax: the pair renders broken `class=""="[ ... ]"`, and nesting `@js()` inside makes it worse. Build the class string in PHP and emit a plain `class="{{ ... }}"`.

## Roles & Filament
- Roles are a plain `role` ENUM on `users` (`super_admin`/`admin`/`editor`/`reporter` in `App\Models\User`) — **not** Spatie Permission. `isSuperAdmin()` = super_admin; `isAdmin()` = super_admin ∪ admin; `isEditor()` = super_admin ∪ admin ∪ editor. `canAccessPanel()` lets all four roles in, so per-page gating is what actually restricts people.
- Panel access is gated per page by the `RestrictsAccessByRole` trait (`app/Filament/Concerns/`): override `requiredRoleCheck()` to `'isSuperAdmin' | 'isAdmin' | 'isEditor'`; default is `isEditor`. `canAccess()` returns 403 and hides the nav item. **No policies exist — if you add a new resource, add the trait.**
- Current gates: `UserResource` = `isSuperAdmin`, `SettingsPage` = `isAdmin`, everything else that uses the trait = `isEditor`, `Profile` = open to all roles (no trait). `ArticleResource` uses the default `isEditor` gate, so reporters are locked out entirely — its `getEloquentQuery()` `author_id` filter is currently unreachable dead code.
- `app/Filament/Widgets/StatsOverview.php` and `LatestArticles.php` (plus `resources/views/filament/widgets/stats-overview.blade.php`) **are registered**: `AdminPanelProvider:64` calls `discoverWidgets(in: app_path('Filament/Widgets'), for: 'App\Filament\Widgets')`, and `->widgets([...])` at `:77` *appends* rather than replaces (`HasComponents.php:171` spreads onto the existing array). Verify with `Filament::getPanel('admin')->getWidgets()` instead of reading the `->widgets([...])` call alone.
- **`FileUpload` state must be a path that exists on the configured disk, never an external URL.** Filament resolves previews server-side through `Storage::exists()` + `Storage::url()` in `BaseFileUpload::getUploadedFileUsing()` (`vendor/filament/forms/src/Components/BaseFileUpload.php:144`), and the browser fetches it via a Livewire round-trip to `getFormUploadedFiles()` (`resources/views/components/file-upload.blade.php:44`) — the preview `<img>` ships with **no `src`**. A missing file yields `null`, so the image silently never appears and flickers. Seeded images therefore come from the `GeneratesPlaceholderImages` trait (`database/seeders/Concerns/`), which writes real PNGs via GD to `storage/app/public/{featured,ads}/` with slug-derived names (idempotent, no font-file dependency). `PublicPagesTest::test_seeded_images_are_files_on_the_public_disk` guards this. The `Article`/`Advertisement` accessors still accept `http(s)://` values for hand-pasted URLs, so the public site can render them — only the admin preview needs a real file.
- `UserResource` disables the `role` select on your own record, so a super admin cannot demote themselves.
- Panel: `/admin` (`AdminPanelProvider`), auto-discovers `app/Filament/Resources`, `Pages`, `Widgets`. Custom Filament view overrides live in `resources/views/filament/**` (login, manage-headlines, profile, settings-page, brand-logo, stats-overview). The panel `brandName` is hardcoded `SULTRAKLIK`, while the public site reads `general.name` — they can drift.
- **Custom Filament page views must be a single-root fragment, not a full document.** `BasePage::render()` already applies `static::$layout` (`filament-panels::components.layout.simple` for `SimplePage`, `...layout.base` for `Page`), so wrapping a view in `<x-filament-panels::page.simple>` / `::layout.base` produces nested `<html>` documents and Livewire throws `MultipleRootElementsDetectedException` whenever `app.debug=true` (which it is here). Write one root element and style Filament's own chrome away with CSS — the login view does this via `display: contents` on `.fi-simple-main-ctn` / `.fi-simple-main` plus `.fi-simple-layout { display: block }`. `AdminPagesTest::test_login_page_renders_with_custom_layout` sets `app.debug=true` on purpose to guard this.
- If the panel suddenly renders markup from a much older Filament (e.g. `min-h-dvh`, `fi-simple-page`), the compiled Blade cache is stale — `php artisan view:clear` (or `optimize:clear`) fixes it. Filament here is 3.3.55: no `Action::submitLoadingLabel()`; `TextInput::revealable()` already renders the eye toggle.
- `Article::booted()` sanitizes content, normalizes slug + video URL, and enforces `is_headline` XOR `is_featured` on save (headline wins, and it also checks the `Headline` table). Don't fight any of these in forms.
- Article body uses `kahusoftware/filament-ckeditor-field` with `->uploadUrl('/upload-image')`. That route is `auth` + `throttle:30,1` only — the `isEditor()` check is `abort_unless(...)` **inside** `UploadController::image()`, which re-validates via `getimagesize()` against a jpg/png/gif/webp allowlist and names files `uploads/ckeditor/{slug}-{random16}.{ext}`. Filament `FileUpload` fields bypass this route and use the `public` disk directly.
- Filament rate-limits login 5×/min per IP; `App\Filament\Pages\Auth\Login` adds 8 failures per email+IP / 15 min and 20 per email / hour, hit only on failure and cleared on success.

## Video YouTube
- `articles.video_url` holds **only** the canonical `https://www.youtube.com/watch?v=<11-char id>`; `Article::booted()` runs `normalizeVideoUrl()` on every save, storing the canonical form or `null`. Never render the raw column — the id is the only trusted value.
- `Article::youtubeId()` is the single parser (`Article.php:181`): accepts `youtube.com/watch`, `youtu.be`, `/embed`, `/shorts`, `/live`, `youtube-nocookie.com`, `m.`/`www.`, and extra query params. Everything else returns `null`. Derived accessors: `youtube_id`, `video_thumbnail_url` (`i.ytimg.com`), `video_embed_url` (`youtube-nocookie.com`), `hasVideo()`; `seo_image` falls back to the thumbnail so video articles still get an OG image.
- The article page player is a **click-to-load facade** (`articles/show.blade.php:49-64`): thumbnail + play button, then Alpine swaps in a `youtube-nocookie.com` iframe with `autoplay=1`. Nothing third-party loads until the click.
- The home "Video" section (`home.blade.php:168-207`, max 4 cards, server-capped in `HomeController`) is a **different** interaction: a horizontal snap carousel where hovering previews the video **muted** (`mute=1`) and the play button pins it unmuted. Do not assume the article page's facade applies here.
- Admin only needs a link: the "Video YouTube" section in `ArticleResource` is a `TextInput` + live thumbnail `Placeholder`. Filament's `->rules()` **evaluates array items as component callbacks**, so a raw closure rule throws `BindingResolutionException` — custom validation must be a rule object (`app/Rules/YouTubeUrl.php`).
- CSP `frame-src` allows `www.youtube-nocookie.com` / `www.youtube.com`; `img-src` already allows any `https:`. `HtmlSanitizer` drops `iframe`, so the player must stay in Blade, never in the article body.
- `tests/Fixtures/DemoContentSeeder.php` membuat satu artikel video terpublikasi dengan bentuk URL `watch?v=` agar normalisasi YouTube tetap ter-cover test — seeder video produksi sudah dihapus.

## Night mode (public)
- Public night mode is a **CSS override layer**, not Tailwind `dark:` variants: `public/css/night.css` recolors the utilities the site actually uses (`.bg-white`, `.bg-gray-50/100/200`, `.text-gray-900/700/600/500/400`, `.border-gray-100/200/300`, `hover:bg-gray-50`, `.article-body`, inputs) under `[data-theme="dark"]`. **Any new public color utility must be added there too, or it stays light.** Overlays (`bg-black`, `from-black-90`, `text-white`/`text-gray-300`) are intentionally left alone — already dark.
- The attribute is set by an inline script in `<head>` (layout `:36-46`) **before first paint** from `localStorage['sultraklik-theme']`, falling back to `prefers-color-scheme`, so there is no flash. `color-scheme: dark` follows so native controls and scrollbars adapt.
- Filament `/admin` has its own built-in dark mode; `night.css` does not affect the panel.

## Content security
- `App\Support\HtmlSanitizer` is an allowlist DOM sanitizer (no external dependency). It strips `style`, all `on*`, and `javascript:` URLs, and drops `script/iframe/svg/object/embed/form` wholesale. **If you add a rich-text field, sanitize it on write *and* on render.**
- The article body is the only `{!! !!}` in the public views (`articles/show.blade.php:82`, wrapped in `HtmlSanitizer::clean()` inline).
- `Article::comments()` already has `where('is_approved', true)` baked into the relation. `CommentController::store()` creates through that relation and only gets `is_approved = false` because the attribute is passed explicitly — don't rely on the relation scope.
- `CommentController` caps submissions at 5/hour per IP+UA, on top of the honeypot (`website`) and the 3-second `formed_at` timing check. When an anti-bot field trips it **silently "succeeds" without saving** (same success message) — keep `website` and `formed_at` in any comment form. New comments are unapproved; likes toggle per IP via `article_likes.ip_address`.
- `App\Http\Middleware\SecurityHeaders` (appended in `bootstrap/app.php`) sets nosniff / SAMEORIGIN / referrer-policy / permissions-policy plus the CSP in `config/security.php`. The CSP **must** keep `'unsafe-inline' 'unsafe-eval'` (Tailwind CDN, Alpine, Filament inline scripts) and the CDN host list — extend `config/security.php`, don't remove the middleware, when adding a CDN.
- `fonts.bunny.net` belongs in **both** `font-src` and `style-src`: it is Filament's default font provider (`HasFont::$fontProvider` = `BunnyFontProvider`), which injects a `<link rel=stylesheet>` to `https://fonts.bunny.net/css?family=...`. `font-src` alone is not enough — the stylesheet itself is fetched under `style-src` and gets blocked otherwise.
- `AppServiceProvider::boot()` forces `app.debug=false` in production and turns on secure/samesite cookies when `APP_URL` is https. Don't rely on `.env` alone.

## Settings
- Single `settings` table keyed by (`group`, `key`). `Setting::get('theme.primary_color')` splits on the first dot; a flat key falls back to the `general` group. `Setting::get()` hits the DB on every call (no cache) — fine at current volume, but don't call it in loops. The Blade layout calls it ~20× per page render, and the nav/footer query `Category`/`Region`/`Page` inline.
- Theme keys are consumed in three independent places: the layout's Tailwind scale override, `public/css/night.css`, and `AdminPanelProvider`'s `->colors()`. A new theme key means touching `SettingsPage` **and** every consumer.
- `SettingsPage::save()` maps form field names → group with a `match`; `mount()` fills the same names. Keep them in sync, or the value silently round-trips to the wrong group. SEO fields are prefixed `meta_` because `description` would collide with `general.description`. Adding a field also needs the group added to the `match`.
- SEO keys `seo.meta_title` / `seo.meta_description` / `seo.meta_keywords` are the site-wide defaults consumed by the layout (title, description, keywords, og:*, twitter:*, and JSON-LD `NewsArticle`). Resolution order: page value → site default → `general.tagline` (description) / `general.name` (title). Home passes no `title` at all so it uses `seo.meta_title`. Article/page views pass `seo_title ?: title` and `seo_description ?: excerpt` — never `??`, an empty string must fall through to the site default.
- `db:seed` overwrites settings (`updateOrCreate`), so re-seeding discards admin edits.

## Tests & factories
- `phpunit.xml` forces in-memory SQLite (`:memory:`, `CACHE_STORE=array`, `SESSION_DRIVER=array`, `QUEUE_CONNECTION=sync`), so the suite passes with MySQL stopped. All four Feature classes use `RefreshDatabase`.
- `PublicPagesTest` runs `DatabaseSeeder` in `setUp`; `AdminPagesTest`, `SettingsTest`, and `SecurityTest` do not — `AdminPagesTest` creates its admin by hand. Seed explicitly in any new DB-touching test.
- `database/factories` contains **only** `UserFactory` — no factories for Article/Category/etc. Build records manually or lean on seeders.
- `tests/Feature/SecurityTest.php` guards the role gates, upload route, sanitizing, reserved slugs, security headers, comment/view rate limits, and the YouTube rule — run it (`--filter=SecurityTest`) after touching any of those. `tests/Unit/HtmlSanitizerTest.php` is a pure PHPUnit test (no app boot) with XSS payload cases.
- `PublicPagesTest::test_public_pages_render` smoke-tests most public routes; it will fail if you break the home/category/region/search/rss/sitemap/article pages.

## Layout map
- `app/Filament/Resources/` — admin CRUD (Article, Category, Region, Tag, Media, Comment, BreakingNews, Page, Advertisement, User), each with `Pages/` and optional `RelationManagers/`.
- `app/Http/Controllers/` — public controllers; `Admin/UploadController.php` is the only admin-only HTTP endpoint.
- `resources/views/` — public Blade; `components/` holds reusable cards/layout/sidebar, `seo/` holds RSS + sitemap.
- Login dev: hanya `admin@sultraklik.id` (super admin) yang dibuat seeder, password dari `SUPER_ADMIN_PASSWORD` atau acak di lokal. Akun `editor@` / `reporter@` tidak lagi di-seed — buat lewat `/admin/users` bila butuh.
